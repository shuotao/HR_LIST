# default — **MEP 工程師** 角色 overlay（v9.2 起涵蓋廠務 + MEP 設計合一）

> **這是 v9.2 起的雙角色架構之一**。本專案歷史上始終只有 2 個角色：`default` (MEP) 與 `space-manager`。v9.0~v9.1 過渡期錯誤拆分為 3 類（多出 `mep-design`），v9.2 已修正合併——所有原 mep-design overlay 規則已併入本 default。
>
> 程式碼權威來源：`screen_candidates.py:get_overlay('default')`。

---

## 一、角色定義

中鼎工程系統部「MEP 工程師」職缺，涵蓋兩種互相支援的工作風格（同一職務的不同面向，非獨立物種）：

**做廣（廠務 / 一般 MEP 統合）**：
- 高科技廠房廠務（半導體 / 面板廠的 UPW/WWT/特氣/PCW/CDA 等公用設施）
- EPC 建廠 / 擴廠專案的施工與監造
- 機電工程的發包、品管、採購、工地管理
- 傳統商辦 / 公共工程的 MEP 監造

**做深（MEP 系統設計）**：
- 用 BIM（Revit / Navisworks）做機電系統設計
- 高科技廠房（半導體 / 面板）MEP 設計圖、施工圖、套圖整合
- 設計階段的 CSD / SEM、設備選型、管線排佈、Hook-up

**風格**：做廣與做深合一。BIM 為基礎工具（非獨立技能軸）。

## 七、樣本特徵（典型誤選輪廓）

### 正面樣本（歷史已入選者特徵）

- 高科 EPC 公司（漢唐、帆宣、亞翔、聖暉、千附）的廠務 / 工程師
- 大陸工程、互助營造的機電主任
- 中鼎、泰興、達欣的建廠工程師
- 國中學歷但機電主任 10+ 年（學歷可寬）
- AECOM、科進栢誠等顧問公司的機電設計（雖學歷土建但有深厚 MEP 設計）

### 反面樣本（典型誤選輪廓 → 已沉澱為 E 條件）

- 軟體工程師、業務、研發、光電製程
- 大樓物業、商場維護
- 工地主任無 MEP 字眼（純土建；E4 加強）
- 餐飲 / 門市轉型且工程經歷單薄
- 純 BIM 建模員（短期 4 段以下）無設計字眼（E21）
- 純廠務維護無設計/建廠/EPC 字眼（E15 加強）
- 非機電對口學歷 + 知名企業多年 + 泛用工程師/副理 + 零 MEP/BIM 字眼（E22）
- 純結構/土木技師軌跡 + 全職涯做結構（E23）
- 大廠廠務退階為工地主任 + 希望職稱轉土建（E24）
- 在學中候選人 + 工作經歷皆為海外/非正式組織（E25）
- 履歷極度單薄缺乏 MEP 實質深度（E26）
- 建築背景跨機電且頻繁跳槽（E27）
- 非工程背景且僅為繪圖員（E28）
- 純 BIM/繪圖且跳槽頻繁（E29）

詳見 `iteration_log.md` Batch 1-32 的累積案例與 v9.2 合併紀錄。
